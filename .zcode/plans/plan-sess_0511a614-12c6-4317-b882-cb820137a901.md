# 移动版 Scheduler Management（admin 专属）

## Context

桌面端已有 admin 专属的 Scheduler Management（`/scheduler`，`SchedulerPage.tsx` 卡片视图：启停开关 / 调度配置 / 快捷操作 / 执行历史入口）。手机端目前的问题：
1. 移动端头像下拉菜单（`MobileLayout.tsx:96-105`）只有 API Keys 和 Monitoring，**没有 Scheduler 入口**；
2. 手机访问 `/scheduler` 时直接渲染 2268 行的桌面版页面，无移动适配。

目标：新增移动版页面 + 在移动端用户菜单 **API Keys 正下方**加入口，仅 admin 可见可用（沿用现有 `AdminRoute` 守卫，与桌面版同口径）。

## 改动内容（纯前端，无后端改动）

### 1. 新建共享模块 `web-frontend/src/config/schedulerSources.tsx`

从 `SchedulerPage.tsx` **原样搬移**并导出（避免移动页 import 桌面页导致整个桌面 chunk 打进移动端分包）：
- 类型 `SchedulerCategory` / `DataSource` / `QuickAction`（SchedulerPage.tsx:134-157）
- `INITIAL_SCHEDULER_DATA_SOURCES`（:189-858，约 670 行卡片定义）
- 排序工具 `getDefaultCategoryOrder` / `mergeCategoryOrder` / `getDefaultCategoryOrders`（:167-187）
- 新增导出 `isTaskRelatedToSource(sourceId, taskType)`：从 `toggleDataSource` 里那段 source→task 映射谓词（:1249-1290，最完整超集）抽取；SchedulerPage 中 3 处内联重复谓词（syncDataSourceStatus :941、getRelatedTasks :1018、toggleDataSource :1254）统一改为调用它（已核对：模糊匹配规则覆盖显式规则，对现有全部 source id 行为等价）。

### 2. 重构 `SchedulerPage.tsx`（行为不变）

- 删除已搬移的定义，改为 `import { ... } from '../config/schedulerSources'`；
- 3 处内联谓词替换为 `isTaskRelatedToSource`；
- 其余（dnd 排序、弹窗、快捷操作）不动。

### 3. 新建 `web-frontend/src/pages/MobileSchedulerPage.tsx`（+ 同名 .css）

复用：`schedulerAPI`（services/scheduler.ts）、共享模块、`DataSourceConfigModal`、`useDashboardSettings` 主题、`getModalStyles`。UI 模式参照 `MobileFeedsListView.tsx`（Segmented 筛选 + 卡片列表 + Switch）与 `MonitoringPage` 的 isMobile 内联样式：

- 顶部：标题 + 刷新按钮；统计行（Data Sources / Enabled / Scheduled 数）
- `Segmented` 分类筛选：All / 数据获取类 / 报告生成类
- 数据源卡片纵向列表，按用户已保存排序展示（`schedulerAPI.getCardOrder()` + `mergeCategoryOrder`，移动端只读不拖拽）：名称、状态 Tag、描述、cron 摘要、卡片级启停 `Switch`（批量启停关联任务，含 `eodhd_fundamentals` 仅手动触发例外，逻辑同桌面 `toggleDataSource`）
- 点卡片展开：关联任务明细（任务名、cron/interval、时区、next/last run、成功/失败计数、单任务启停 Switch，`schedulerAPI.enableTask/disableTask`）；快捷操作——Configure 复用 `DataSourceConfigModal`（传 dataSourceType/name + initialCron/timezone，同桌面），直跑类操作 `api.post(action.endpoint, params)`（同桌面 `executeQuickAction`）
- 「执行历史」入口：`navigate('/monitoring?tab=scheduler')`（已有移动端适配的 TaskExecutionHistory）

### 4. `MobileLayout.tsx`：加入口（API Keys 正下方）

在 `/settings/api-keys` 项之后插入（:103-105 Monitoring 之前）：
```tsx
...(user?.is_admin
  ? [{ key: '/scheduler', icon: <ControlOutlined />, label: 'Scheduler Management', onClick: () => navigate('/scheduler') }]
  : []),
```
图标/文案与桌面 `Layout.tsx:208` 完全一致；同步更新 :70 的注释。

### 5. `TerminalRoutes.tsx`：设备切换路由

- `const MobileSchedulerPage = lazyWithRetry(() => import('./pages/MobileSchedulerPage'));`
- `const SchedulerComponent = isMobile ? MobileSchedulerPage : SchedulerPage;`（:159-164 处，同 Dashboard/Files 模式）
- `scheduler` 路由（:196-203）改用 `<SchedulerComponent />`，保持 `<AdminRoute>` 包裹 → 非 admin 自动重定向 `/feeds`。

Admin 限制实现方式：菜单项 `user?.is_admin` 条件渲染 + `AdminRoute` 路由守卫（与桌面版 scheduler/users/monitoring 页同口径，后端 `/api/scheduler/*` 代理已有 JWT 鉴权，无需改动）。

## 验证

1. `cd web-frontend && npx tsc --noEmit && npm run build`（CRA 构建通过，验证搬移/分包无破坏）
2. dev server + 手机视口（<768px）浏览器验证（用 browser-use）：admin 登录 → 头像菜单 API Keys 下方出现 Scheduler Management → 页面加载、卡片渲染、展开任务明细、打开 Configure 弹窗、Monitoring 跳转；**注意这是疑似生产环境，只做非破坏性检查，不实际拨动启停开关、不提交配置**
3. 非 admin 账号：菜单无此项，直接访问 `/scheduler` 被重定向到 `/feeds`
4. 桌面回归：≥768px 视口下 `/scheduler` 仍为原桌面版页面，功能不变

# reports 模块新增 Morning Brief（facts-report）— 定稿方案

## Context

facts-report 现由服务器 crontab（08:00 周二至六）启动 LLM agent 管线：`cron_daily.sh` → `build_snapshot` → `show_gate`（就绪门+Lark 告警）→ `run_pipeline`（40–60 分钟、单次 ~12M tokens）。目标：按用户最初需求"參考 DMR、通过 Scheduler 在指定时间生成并保存至数据库"——**Scheduler 定时触发、HTML 上传阿里云 OSS、持久化到专用表、经只读 API 服务**。全局单例（无 user 维度）。

**角色边界（本次澄清定稿）**：Scheduler 是纯后端闹钟（rc-scheduler + `task_scheduling` 表），前端零接触；前端只读报告 API；无任何手动触发面。

**硬约束**：不允许用户手动触发（管线重、并发跑会压垮服务器）。生成入口唯一 = task_scheduling cron；人工补跑走服务器 CLI（bash cron_daily.sh 或直调 celery task 带 force），不经 HTTP。

**OSS 惯例（照 twitter_daily_report_service.py:750-816）**：`OSSService().upload_bytes(object_name, html, 'text/html')` → DB 同存 `html_content` + `oss_object_name`；OSS 失败不致命；`get_report_html_by_token` DB 优先、OSS 兜底。

## 架构

```
task_scheduling (type=morning_brief, cron 0 8 * * 2-6, Asia/Shanghai, period_key 分布式锁)   ← 唯一生成入口（后端闹钟）
 → SchedulerService._execute_morning_brief_task   [复用 DMR shim 模式]
 → celery generate_morning_brief (queue=data_fetching, 秒级返回)
    ├─ 当日已有 completed 行且非 force → 跳过（防误派发；force 仅 CLI 可达）
    ├─ MorningBriefReportService.mark_generating(北京日) + 孤儿回收(>4h generating→failed)
    └─ setsid nohup bash cron_daily.sh (detached, >> cron.log；自带 ZCODE env + flock 防并发)
        → build_snapshot → show_gate(Lark ⚠️/🔴) → run_pipeline
        → register_morning_brief.py（发布注册器）
             ① 富版 report.html（md2html_report.py），失败回退 mistune 简版
             ② OSSService().upload_bytes("reports/MorningBrief/report_<北京日YYYYMMDD>.html")（失败不致命）
             ③ svc.complete / svc.fail（html_content + oss_object_name 落库）
 → 前端只读 API /api/morning-brief-report/{latest,list,shared/{token}}
```

**四层防误触发**：① 无触发类 HTTP 端点（也不新增调度管理端点，schedule 走 seed 迁移/DB）；② celery 任务先查当日 completed 行，非 force 即跳过；③ `cron_daily.sh` flock 挡并发；④ Scheduler period_key 分布式锁。

## 关键设计决策

- **触发面唯一**（Scheduler cron）；cutover 后 crontab 08:00 行注释保留，可随时回滚
- **完成态由管线侧回写**（唯一事实源），不做轮询扫描器；detached 子进程不占 celery 槽
- **report_date=北京自然日**（"今早简报"语义）；`metadata.session_date`=美股交易日 T（工作区目录名）
- **DB `html_content` 与 OSS 同存**：OSS 故障时 `/shared/{token}` 服务不中断
- （二期可选）`agent_service.py` kind map 加 `'morning_brief'`（同样只读）

## 实施顺序与验证

1. **Phase 1 骨架**：migrations + db_manager + scheduler + celery task + service → 验证：建表/seed 落地；手动派发一次在 `task_execution_logs` 留痕
2. **Phase 2 发布注册**：cron_daily.sh + register + 兜底模板 → 验证：对现有 2026-11-09 工作区执行 register（不重跑管线）：DB 行 completed、富版 HTML 生成、OSS 可见 `reports/MorningBrief/report_20261110.html`、`/shared/{token}` 返回完整页面
3. **Phase 3 API** → 验证：`/latest` `/list` `/shared/{token}` 只读可用；**确认无任何触发端点**；重复派发 celery（模拟误触）第二次被 completed 行挡下
4. **Phase 4 cutover**：启用 task_scheduling 行；观察一次 Scheduler 自然触发（08:00）成功后，注释 crontab 08:00 行；show_gate/Lark 告警链路原样生效

# 让用户可以修改 Sources 显示名称（LLM 命名）

## Context（问题根因）

Upload sources 卡片上显示的名字是 `first_display_name`（LLM 自动命名，`file_processing_details.display_name`）|| `first_filename`（源文件名）。

现有 "Rename" 功能的局限：
- 弹窗预填的是**源文件名** `first_filename`（不是卡片上显示的 LLM 名），且强制保留扩展名 —— 它编辑的是 `filename` 字段
- 后端 `PATCH /executions/{id}/rename`（`backend/api/tasks.py:546`）只更新 `filename` 并把 `display_name` 置 NULL；**没有任何接口能把 `display_name` 设为用户自定义值**（该字段目前只有 LLM 服务 `content_naming_service.py` 一个写入方）
- 竞态问题：自动命名 Celery 任务开始时读到 `display_name` 为空，用户在 LLM 调用期间设置名称后，任务完成时仍会无条件覆盖（`save_display_name` 是无条件 UPDATE）

## 方案

Rename 弹窗改为直接编辑**显示名称**（用户看到什么就改什么）；源文件名保持不变。留空保存 = 恢复显示源文件名。

### 后端（2 个文件）

1. **`backend/api/tasks.py`**
   - 在 `RenameExecutionRequest`（line 485）旁新增 `UpdateExecutionDisplayNameRequest(BaseModel): display_name: Optional[str] = None`
   - 新增端点 `PATCH /api/tasks/executions/{execution_id}/display-name`，仿照 `update_execution_final_report`（line 493）的归属校验模式：
     - 校验 execution 归属当前用户（同现有 rename 端点）
     - 取该 execution 首个文件（`ORDER BY id ASC LIMIT 1`，与列表页 subselect 一致）
     - `display_name = (body.display_name or '').strip()`，空 → `NULL`（恢复显示源文件名）；截断到 200 字符防滥用
     - `UPDATE file_processing_details SET display_name = %s WHERE id = %s`，返回 `{message, display_name}`
   - 旧 `/rename` 端点保留不动（兼容）

2. **`backend/services/content_naming_service.py`**
   - `save_display_name`（line 180）加 `force` 参数：非 force 时改为条件更新 `WHERE id = %s AND display_name IS NULL`，rowcount=0 则记日志跳过 —— 防止在途 LLM 命名任务覆盖用户手动设置的名称；`name_file_content`（line 157 调用处）透传 `force`

### 前端（3 个文件）

3. **`web-frontend/src/services/tasks.ts`**：新增 `updateExecutionDisplayName(executionId, displayName)` → `PATCH /tasks/executions/{id}/display-name`

4. **`web-frontend/src/pages/FilesPage.tsx`**（桌面端，handlers 1534–1572，弹窗 3729–3760）：
   - `handleOpenRename`：预填 `execution.first_display_name || stem(first_filename)`（用现有 `filesAPI.splitFilenameStemAndExtension` 取 stem）
   - `handleConfirmRename`：改调 `updateExecutionDisplayName`；乐观更新 `first_display_name`（空输入 → `null`），同步更新 `selectedExecutionForView`
   - 弹窗：改为单一"显示名称"输入框（去掉扩展名 addon），允许留空并提示"留空则恢复显示源文件名"；okButton 不再因空值禁用

5. **`web-frontend/src/pages/MobileSourcesPage.tsx`**（移动端，handlers 532–562，弹窗 1443–1467）：同样修改

`MobileSourceFileDetail.tsx`、表格视图、分享页等展示处都是 `first_display_name || first_filename`，自动生效，无需改动。

## 验证

- 后端：`python -m py_compile backend/api/tasks.py backend/services/content_naming_service.py`
- 前端：`cd web-frontend && npx tsc --noEmit`（仅类型检查；裸 `npm run build` 在此服务器上有 OOM 防护禁止直接运行）
- 手动验收（部署后）：上传文件 → 等 LLM 命名出现 → Rename 改成自定义名（无扩展名限制）→ 卡片/详情显示新名；清空保存 → 恢复显示源文件名

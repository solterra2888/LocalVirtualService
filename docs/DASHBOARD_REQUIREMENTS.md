## 1. 背景与产品定位

### 1.1 为什么需要 Dashboard

现有日报（Daily Report）是**日度高频数据**的展示；但另一类数据（宏观、央行、13F、地缘、主题演化等）**不是日度更新**，团队又需要不时观察。目前只能"需要时再去搜"，信息获取割裂。

Dashboard 的定位是一个**仪表盘（Instrument Panel）**：集中、持续地呈现这些中低频数据，需要时一眼可查，而不是对日报里所有 chart 逐一观察两分钟才能形成市场判断。

### 1.2 与日报 / Feed Digest 的关系

| 产品 | 定位 | 组织方式 |
|---|---|---|
| Feed Digest | 原始信息层：从各信息源抓取的概要 | 按信息源 / 发布人 |
| 日报（Daily Report） | 日度高频数据 | 每日更新 |
| Dashboard | 按投研需求定制的中观仪表盘 | 按投研需求模块化 |

关键共识：
- Feed Digest 保持"从信息源出发"的定位，不必改造成按需求定制——那是 Dashboard 的职责。Feed Digest 是 Dashboard 的输入之一："已经是我们抓出来的信息，只是比较冗长，不是纯无用的信息"。
- Dashboard 的信息来源 = **Feed Digest 挖掘 + 专项外部数据源**（宏观 API、行情筛选、13F 披露等）。Feed Digest 里找不到的（如厄尔尼诺专项指标），需要另行开发数据源。
- 另有讨论（**未做结论**）：Feed Digest 目前按发布人归类，阅读意愿低；后续可探讨参考 Dashboard 的内容结构 / 按投资主题重新归类组织。

### 1.3 核心价值主张

- **1 秒感知市场温度**（Header 牛熊 + 最热/最差板块 + Top Stock）
- **主题/矛盾线的持续跟踪**：投资 thesis 记录下来后，相关信息自动归集到时间线上，避免靠人工随机发现而错过行情（如商业航天第二波）
- **新闻端 × K 线端交叉验证**：新闻催化（地缘/主题）与技术形态（创新高/平台突破/底部爆量）本质上都是"投资机会的提醒"，两端信息在 Dashboard 上汇总串联，形成交叉验证
- **提效而非替代**：将人工每日刷图、刷资讯中的"筛选"环节自动化——"把完全不符合的直接过滤掉"，人只对着候选看，刷得更快、效率更高

## 3. 模块详细需求

### 3.1 Header（市场温度条）

页面最上方横向排列四格，目标是"1 秒钟直观 grasp 市场温度"，是日报的精炼与补充：

| 格子 | 内容 |
|---|---|
| 1 | 当下市场整体处于 **Bullish / Bearish** |
| 2 | **Hottest Sector**（出一个即可，附涨跌幅） |
| 3 | **Worst Sector**（附跌幅） |
| 4 | **Top Stock**（涨幅最多的大市值个股） |

展示要求：直观优先，不重复日报里已有的 sector distribution 详情（"再去搞颜色这些东西就和日报重复了"）。

**待定问题**：
- Bullish/Bearish 如何定义？两条路径各有利弊：
  - a. **量化规则**定义：可控，但考虑可能不全
  - b. **AI 判断**：结合 Feed Digest + 外部数据 + 日报指数行情综合判断：考虑全面，但未必可控
- 板块分类口径：GICS 11 板块，还是按市场当期主题/thesis 动态分？小肖倾向后者，但 thesis 每日变化、如何确定使用哪些 thesis 尚未解决
- 位置：放 Dashboard 还是日报（提纲已标注"可考虑放在日报"）

### 3.2 宏观（✅ 可做）

美国宏观指标（美股为主战场；这些数据也是 Fed 议息的输入，辅助观察美联储动向）：

| 指标 | 展示 |
|---|---|
| CPI、核心 CPI | 绝对值 + 同比/环比（YoY / MoM 或 QoQ）变化趋势 |
| PPI | 同上 |
| 非农就业 | 同上 |

展示目标：能看出趋势处于延续、出现拐点还是加重状态。

**数据源**：<https://eodhd.com/financial-apis/economic-events-data-api>

### 3.3 央行（✅ 可做）

**美联储**：
- 最近一次 FOMC 会议纪要概括
- 最新 updates（正式会议之外，美联储关键人物的表态）
- 加息/降息概率统计（可从预测市场/事件下注网站或已有统计直接取数或嵌图）

**中国央行 / 日本央行**（两者结构一致）：
- 货币/财政政策发布要闻
- 最新表态 updates

**数据源**：Kevin 提到美联储系官网提供系列更新 API（逐字稿口述为 "fat series updates"，疑为 **FRED**，待确认）。

### 3.4 地缘（⚠️ 复杂，先放一放）

三个层级：

1. **当下进行中的地缘冲突**（当下是美伊）
   - 简要事件梳理：非常简洁地阐述清楚这是什么事件、发生了多久、目前什么状态（AI 定义事件归属后做梳理，强项在于此）
   - 各方最新表态：美国、伊朗怎么说的；阿曼、沙特、阿联酋等相关方如何表态
   - KOL 观点分享：靠谱、有影响力的相关专家对当下局势的判断
2. **中美关系头条要闻**：元首会晤、贸易管制、科技限制等
3. **潜在地缘风险**：中日、台海等有无更新

**实现路径讨论**（Kevin）：
- 路径 A：人工定义地缘 thesis，系统每天/每周自动汇聚相关新闻
- 路径 B：AI 自动检测并生成地缘 thesis，自动更新
- **共识：两者结合**。美伊、美中这类重点 thesis 系统可以检测出来；但纯 AI 自动会产生大量噪声主题（"津巴布韦怎么了，who cares"），必须叠加 AI 判断做重要性筛选，边做边看
- Kevin 评估：本质是**数据挖掘与筛选工程**，可做（是其擅长），但没想象中容易

### 3.5 主题 / 矛盾线时间记录仪

**概念**：投资 thesis（今后可能产生的投资机会）在提出时市场未必有反应；记录下来之后，通过**时间线**持续跟踪相关新闻与板块市场效应，观察主题在不同阶段的发展。

**案例**：
- **厄尔尼诺**：小肖一个多月前提出时市场尚无反应（期货市场略有体现）；近期中国市场农业板块走出两天行情。判断依据不只是新闻刺激——CBOT（芝商所）三大主粮价格真实受到全球气温变化影响（印度、欧洲已现端倪）。**新闻刺激是次要的，粮食价格变化是主要的**。
- **商业航天**：上一波行情（十五五规划出台时）因敏感度不足没有抓住；当时也关注了火箭回收能否成功（此前未成功）。2026-08-19 朱雀三号遥二运载火箭成功发射，一子级按预定程序精准垂直着陆，我国首次实现轨道级运载火箭陆地垂直回收——标志中国商业航天从"能够发射"迈向"可重复使用"，可能迎来第二波行情。"这条投资主线我们没有放弃"。若靠人工随机发现新闻（等群里传阅时说明已经爆了、特朗普会员制也只能提前不到 1 秒），一定会错过。

**需求要点**：
- 主题（thesis）由**人工定义**（郑翔明确表示不完全信任 AI 自动挖掘主题；人工定义也使实现难度减半）
- AI 负责把 Feed Digest 及外部信息**自动归类**到对应矛盾线/主题下
- 针对特定主题（如厄尔尼诺）需先**人工建立领域知识**：什么是厄尔尼诺/拉尼娜、周期是什么、观察点是什么——在此基础上确定要挖的数据与数据源；Feed Digest 中出现的相关内容同时归入
- **时间线展示**：主题下相关新闻 + 股票市场板块效应，按时间排列，跟踪主题在不同阶段的发展

**主题发现机制**（大雄建议，会议通过）：
- AI 主动分析并提出**潜在新主题候选列表**，人**手动确认/添加**——半自动化（"能自动化尽量自动化，但不要完全自动化把人坑死"）
- 备选方式：借用大平台已有主题库（如金石数据的主题分类）

### 3.6 Watchlist（✅ 相对可做）

**个性化**：每位用户有自己的 watchlist → Dashboard 因人而异，"每个人看到的都不太一样"。

内容：
- 个股 **charts**
- **期权情绪**（三类口径——"期权是风险偏好最高的人对股票观点的表达"）：
  1. 30-day ATM IV（30 天平值隐含波动率）
  2. Call/Put 当日成交比（谁买得多、谁卖得多）
  3. Call/Put 持仓量比
- **大单监控**：watchlist 内个股异常大单买入/卖出（口径类似同花顺/iFinD 的"大单/中单/小单"栏目）
  - ⚠️ Kevin：EODHD/Yahoo Finance 未必提供此数据，一般券商才有，普通人未必拿得到；**先调研，可以放后面**

### 3.7 个股形态筛选（✅ 可做，定义待定）

**定位**：不是针对某一只股，而是**全市场扫描**（独立于 watchlist 的新栏目）。与郑翔"龙头战法"的人工刷图流程高度重叠——**本质需求是"提醒现在市场资金在做什么，尽早给到投资线索的提醒"**。它不替代人工，而是先过滤掉完全不符合的票，人直接对着候选看。

**数据口径**：日频、**收盘后**跑即可，不需要盘中实时——"从来不在盘中做 watchlist 之外的票，盘中追风胜率低，以收盘为主"。

三类形态（每类均需：chart + 行业协同 + 新闻催化）：

1. **创新高个股**
   - chart
   - **反向归因**：AI 推断是什么催化剂推涨了新高；优先从我们关注的 feed 中找归因，有思维链论证过程
   - 注：创新高的票大概率不追，重点在下面两类
2. **平台突破个股**
   - chart
   - 所属行业其他个股（有无协同效应）
   - 行业新闻 updates（催化）
   - 定义（郑翔口述）：股价**突破平台区间上沿的最高价**即平台突破；平台是横盘/波段，时长 1-3 个月、6 个月、12 个月不等，肉眼可识别，不框死；高位、低位皆可出现；不归类到"圣杯杯沿"等图形术语。典型样本：小米集团大底部后的平台突破
3. **底部爆量阳线个股**
   - chart
   - 所属行业其他个股
   - 行业新闻 updates

**关键待定**：三类形态的**量化定义**（创新高回看区间是 6 个月还是 1 年、平台如何算法识别、爆量阈值等）——"虽然看起来大家都懂意思，但怎么量化，每个人心里都有不一样的秤和尺子"。由郑翔与小肖线下碰头确定，且**每类提供约 5 个样本（股票 + 具体区间）**供 Kevin 校准。

**新闻端与 K 线端的串联**（郑翔）：地缘/主题是新闻端的提醒，三类形态是市场资金端（K 线）的提醒；两端在 Dashboard 汇总，可能形成串联与交叉验证（最好情况：看到新闻 + 板块个股同步启动）。

**范围**：先做美股。

## 4. 横切需求

### 4.1 AI 事件解读（利多/利空判断）

**需求**（小肖）：目前 AI 产出是纯事件展示，希望增加**对事件的判断和解释**（如此事是利多还是利空），类似他人分享的 AI 投研 dashboard/日报的效果。

**方案**（Kevin）：通过 **skill 文档**实现——以不同方法论（如 Druckenmiller 风格的 skill 文档，或自定义的综合性 skill 文档）解读某种事件/研报。本质是大型 prompt template；系统已有 prompt template 基础设施，skill .md 文档是更新的产物。要定义好需要花功夫，不是随便写几句话。小肖后续对 skill 文档输出反馈。

### 4.2 数据源策略

| 来源类型 | 适用模块 |
|---|---|
| Feed Digest 挖掘（已有信息再加工） | 地缘、主题/矛盾线、个股反向归因、KOL |
| 专项外部 API | 宏观（EODHD）、央行（Fed 系 API 待确认）、13F、行情/期权数据 |
| 领域调研后定向开发 | 主题类指标（如厄尔尼诺 → CBOT 粮价等观察点） |
| 存疑待调研 | 大单监控（券商级数据） |

## 6. 实施优先级（会议共识）

**原则**（郑翔）：
1. **确定的需求先做**（如 13F——相对简单可先做出来；宏观、央行）
2. **不确定的不急着开发**（定义未定的 Header、个股形态——等定义和样本到位）
3. 真正进入开发执行时，**必须先与需求方再确认一次**

**建议批次**：

| 批次 | 模块 | 依据 |
|---|---|---|
| 第一批 | 13F 机构持仓、宏观、央行、KOL 表态 | 确定性高、数据现成 |
| 第二批 | Watchlist（charts + 期权情绪）、个股形态筛选 | 可做，但依赖形态定义与样本（4/5 号待定项） |
| 第三批 | Header（依赖其他模块数据）、主题/矛盾线时间记录仪、地缘 | 依赖前序或方案复杂，迭代推进 |
| 暂缓/调研 | 大单监控 | 数据源存疑 |

**里程碑**：9 月计划团队赴上海集中 1-2 周，现场共同打磨需求与方案。

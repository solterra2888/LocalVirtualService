# 新闻质量过滤方案

> 版本：v1.0  
> 日期：2026-03-18  
> 状态：方案讨论阶段  
> 关联文档：`投研Skill引擎开发方案.md`、`需求文档.md`

---

## 一、背景与问题

当前新闻主要通过 Scheduler 从 EODHD 定期获取。经过多个月数据累积后，**大部分新闻质量一般**，需要在入库、分析与展示全链路引入可配置的过滤与排序能力。

可选方向简述：


| 方向                              | 局限                    |
| ------------------------------- | --------------------- |
| 仅按来源大类（Yahoo、Seeking Alpha 等）筛选 | 只能分大类，无法精细筛走低质量稿件     |
| 仅靠 Agent/Skill 按偏好筛选            | 需与规则、LLM 评分、用户行为结合才稳定 |


本方案采用**三层漏斗 + 反馈闭环**，与现有 `news` 表、`news_classification`、主题筛选及后续 Skill 引擎对齐。

---

## 二、当前系统能力（摘要）

- **数据流**：EODHD API → `news` 表 → 可选 LLM 分析 → 前端展示与筛选。
- **已有筛选**：`ThemeFilterPanel` 支持 `urgency`、`news_value`、`event_type`、sector、country、watchlist 等。
- **主题质量**：`news_themes_unified.quality_score` 描述的是**主题映射**质量，不是**单篇新闻**质量。
- **缺口**：缺少**文章级质量分**；过滤多在展示端，入库端缺少快速预筛与来源信誉管理。

---

## 三、总体架构：三层漏斗 + 反馈闭环

```
EODHD API
    │
    ▼
┌───────────────────────────────┐
│ Layer 1: 入库时规则过滤        │  ← 快速、零 LLM、去除明显垃圾
│ (Rule-based Pre-filter)       │
└───────────┬───────────────────┘
            │ 存入 news（带 pre_filter_score）
            ▼
┌───────────────────────────────┐
│ Layer 2: LLM 质量评分          │  ← 文章级质量分
│ (扩展 news_classification 或    │
│  独立 news_quality_v1)          │
└───────────┬───────────────────┘
            │ analysis_result / quality_score
            ▼
┌───────────────────────────────┐
│ Layer 3: 个性化相关性          │  ← 按用户兴趣二次排序
│ (User Preference Relevance)   │
└───────────┬───────────────────┘
            ▼
        用户看到的新闻流
            ▼
┌───────────────────────────────┐
│ 反馈闭环：用户行为信号           │
└───────────────────────────────┘
```

## 四、Layer 1：入库时规则过滤

**位置**：`eodhd_news_service` 中文章入库前（如 `_process_article_for_db` 阶段）。**不调用 LLM。**

### 4.1 来源信誉表

```sql
CREATE TABLE news_source_scores (
    id SERIAL PRIMARY KEY,
    source_name VARCHAR(200) UNIQUE NOT NULL,

    reputation_score FLOAT DEFAULT 0.5,
    tier VARCHAR(10) DEFAULT 'medium',

    total_articles INTEGER DEFAULT 0,
    avg_content_length FLOAT DEFAULT 0,
    avg_quality_score FLOAT,
    user_save_rate FLOAT,

    is_active BOOLEAN DEFAULT TRUE,
    notes TEXT,
    updated_at TIMESTAMP DEFAULT NOW()
);
```

**示例 tier（可运维调整）**：


| 来源类型示例                                 | tier   | reputation_score（示例） |
| -------------------------------------- | ------ | -------------------- |
| Reuters、Bloomberg、FT                   | top    | 0.90–0.95            |
| Seeking Alpha 等                        | high   | ~0.80                |
| Yahoo Finance 等                        | medium | ~0.60                |
| GlobeNewswire、PR Newswire、AccessWire 等 | low    | 0.20–0.30            |


### 4.2 规则评分逻辑（示意）

- **来源信誉**（约 35%）：查 `news_source_scores`。
- **内容深度**（约 25%）：按正文长度分段给分，过短降权。
- **标的关联**（约 20%）：有 `symbols` 则加分（兼顾无标的的宏观稿）。
- **情绪极端度**（约 10%）：极值情绪略降权（缓解标题党）。
- **近似重复**（约 10%）：标题/链接近似重复则降权。

输出示例：

```json
{
  "pre_filter_score": 0.62,
  "source_tier": "medium",
  "content_length": 1200,
  "symbols_count": 2,
  "filter_reasons": []
}
```

### 4.3 news 表扩展

```sql
ALTER TABLE news ADD COLUMN IF NOT EXISTS pre_filter_score FLOAT;
ALTER TABLE news ADD COLUMN IF NOT EXISTS source_tier VARCHAR(10);
ALTER TABLE news ADD COLUMN IF NOT EXISTS pre_filter_meta JSONB;

CREATE INDEX idx_news_pre_filter_score ON news(pre_filter_score DESC);
CREATE INDEX idx_news_source_tier ON news(source_tier);
```

### 4.4 Scheduler 策略（可配置）


| 模式             | 行为                                                    |
| -------------- | ----------------------------------------------------- |
| **mark**（推荐默认） | 全部入库，低分打标 `source_tier` / 低 `pre_filter_score`，前端默认折叠 |
| **skip**       | 低于阈值不入库（激进）                                           |
| **separate**   | 低分进归档表（中间方案）                                          |

## 五、Layer 2：LLM 质量评分

**目标**：单篇 **overall_quality**（及多维子分），供筛选与排序。

### 5.1 维度建议（1–5 分）

1. **信息密度**：是否有数据、事实、引述。
2. **原创性**：一手/深度 vs 简单改写。
3. **投资相关性**：对决策参考价值。
4. **时效性**：突发/及时 vs 陈旧回顾。
5. **可信度**：来源与论据是否可靠。

附加字段示例：`is_actionable`、`brief_reason`。

### 5.2 与现有流水线集成

- **方案 A**：新增独立模板 `news_quality_v1`，结果写入 `analysis_result`。
- **方案 B（推荐降本）**：在现有 `**news_classification` 一次调用**中增加 `quality_scores` 块，避免多一次 LLM。

`analysis_result` 与便于查询的冗余字段：

```sql
ALTER TABLE news ADD COLUMN IF NOT EXISTS quality_score FLOAT;
CREATE INDEX idx_news_quality_score ON news(quality_score DESC);
```

### 5.3 成本控制

- 仅对 **Layer 1 分数 ≥ 某阈值** 的稿件跑完整分类+质量（可配置）。  
- 质量子任务可选用更小模型（若拆成独立模板）。  
- 优先采用 **与 classification 合并** 减少调用次数。

## 六、Layer 3：个性化相关性（查询侧）

在用户浏览时计算或缓存（不必每篇入库时按用户写库）。

**示意公式**：

- 主题与用户关注 tag 重叠（约 40%）。  
- 标的与 watchlist 重叠（约 30%）。  
- 历史行为/主题亲和度（约 30%）。

**综合排序示例**：

```
final_score = quality_score × 0.5
            + user_relevance × 0.3
            + time_decay × 0.2
```

### 6.1 与主题筛选 API 的扩展

在 `POST /themes/filter/news` 的请求体中可增加：

- `min_quality_score`：最低质量分。  
- `is_actionable`：仅「可执行」类稿件。  
- `source_tiers`：如 `['top','high']`。  
- `sort_by`：`time` | `quality` | `relevance`。

前端：质量滑块、「仅高质量」「默认可执行」等快捷项；可与现有 `urgency` 等组合使用。

## 七、反馈闭环

### 7.1 用户行为表

```sql
CREATE TABLE news_user_interactions (
    id SERIAL PRIMARY KEY,
    news_id INTEGER REFERENCES news(id),
    user_id VARCHAR(100) NOT NULL,
    interaction_type VARCHAR(30) NOT NULL,
    -- view, read_full, save, share, dismiss, thumbs_up, thumbs_down
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(news_id, user_id, interaction_type)
);
```

### 7.2 行为权重（示例）


| 行为                      | 含义     | 权重方向 |
| ----------------------- | ------ | ---- |
| save                    | 收录到研究库 | 强正   |
| share                   | 分享     | 强正   |
| thumbs_up / thumbs_down | 显式反馈   | 正/强负 |
| read_full               | 读全文    | 弱正   |
| dismiss                 | 隐藏     | 负    |


### 7.3 定期任务

- 按 **source** 聚合行为 → 更新 `news_source_scores`（如 `user_save_rate`、`avg_quality_score`）。  
- 校验 LLM 质量分与用户行为相关性，必要时调整 prompt 或阈值。  
- 更新用户侧主题亲和度，优化 Layer 3。

## 八、与 Skill 引擎的衔接


| Skill 建议 ID              | 作用                                          |
| ------------------------ | ------------------------------------------- |
| `news_quality_scorer`    | 入库后批量评分；供日报/对话「今日高质量新闻」调用。                  |
| `personalized_news_feed` | 结合 quality + 用户 tag/watchlist + 行为，对话或定时简报。 |


可与 `投研Skill引擎开发方案.md` 中的 Scheduler、Celery、`SkillContext` 对齐实现。

## 九、实施优先级（建议）


| 阶段      | 内容                                                                        | 周期（参考） |
| ------- | ------------------------------------------------------------------------- | ------ |
| **第一步** | Layer 1：`news_source_scores`、`pre_filter_score`/`source_tier`、前端按 tier 筛选 | 1–2 周  |
| **第二步** | Layer 2：扩展 classification 或独立质量模板、`quality_score`、前端质量筛选与排序               | 1–2 周  |
| **第三步** | Layer 3 + 闭环：`news_user_interactions`、前端轻交互、相关性排序与来源表回写                   | 2–3 周  |


**建议先做 Layer 1**：零 LLM 成本，对 PR 类低质来源默认折叠即可明显降噪。

## 十、待决问题

3. **反馈**：显式 👍/👎 vs 更多依赖隐式行为（停留时长等）。
